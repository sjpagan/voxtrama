{# The workflow-choice panel: one card per workflow (rendering.WorkflowOffer), each its own native form (no JavaScript). Generic: no Recording, no recording_id baked in anywhere, because the Workflows section reuses this macro to offer the same choice starting from the library instead of a recording's row. `action` is the URL every form here posts to. `hidden_fields` is a dict of extra values that submission needs to carry along (today, only `recording_id`) whose meaning this macro has no business knowing. A workflow presents by its readable `title` (workflow. definition.Workflow's field) and what it produces: its `description`, plus `produces` (rendering.workflow_offers' reading of each step's skill, never a hand-written list) shown in the same words as components/run_output.html's "Verified output" filter, imported from there rather than a second translation of the same four nouns. `name`, the file's identifier, still travels (POST /runs and the CLI both take it), but only as the hidden field below, never shown: a person choosing here reads `title`, not the file that backs it. `already_run` maps a workflow's `name` to the most recent succeeded Run api.routes.workflow_choose already found for this Recording, when there is one. It is empty for pages/workflow_library. html's call, which has no Recording to check against, so a workflow shown from the library never claims to already have a result. An offer named there gets "View result" instead of the form: rerunning it blind, with no sign the answer already exists, is the wasted work that was measured. Two levels, decided while this was being built. What everyone touches every time (the workflow and the Start button) stays open. What a run can override (hardware profile, generative model, a step's skill) sits inside a closed
(same element as components/header.html's identity menu), because most runs want the installation's settings and should not have to look at them. Nothing chosen there is submitted unless a select is changed: the blank option is the true default (RunChoices' None, workflow.choices' docstring), never re-submitted as an explicit value, so a run that opened the details and closed it again without touching anything reads exactly like one that never opened it. Each blank option is labelled with the value it stands for ("As configured (base)", not just "Use the default"), so provenance is legible without reading code: is this what the installation already says, or something this run chose. The line right under Start is pure CSS (form:has(select option:not([value=""]):checked), components/ _forms.scss), not a script. It stays hidden until a select inside this same form holds a non-blank value. It is visual only: components/_forms.scss's comment on that rule names who this leaves out, and where an override made in here is still readable afterwards. `offer.available` is false for a workflow whose options are empty or that failed to load at all: it still gets a card, with the reason instead of a form. A dead, silent option reads as a fault (the rule for a deactivated workflow, extended here to a broken one). `selected` names the one offer, if any, a person already picked before landing on whichever page called this macro.
